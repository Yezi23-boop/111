# 硬件能力缺口图

## 已有硬件且代码已接入

- 显示：`CO5300` + `LVGL`
- 触摸：`FT5x06/FT3168` 兼容路径
- 音频播放/录音：`ES8311 + ES7210`
- Wi-Fi 配网：`wifi_provision`
- 存储：`SPIFFS` + `SD` 卡

## 原理图可见但当前代码未见接入

- `AXP2101` 电源管理
- `PCF85063ATL` RTC
- `QMI8658C` IMU
- 与 PMIC/RTC 相关的 `AXP_IRQ`、`PWRON`、`PWROK`、`RTC_INT`

## 证据边界

- 以上“未见接入”基于对 `main/` 和 `components/` 的代码搜索：
  - 未检出 `AXP2101`
  - 未检出 `QMI8658C` / `QMI8658`
  - 未检出 `PCF85063ATL` / `PCF85063`
  - 未检出 `AXP_IRQ` / `PWRON` / `PWROK` / `RTC_INT`
- 这表示当前仓库里没有明显的板级驱动或业务接线，不等于硬件不可用。

## 当前功能与 UI 的差距

- UI 资源里已经有心率、AI、游戏、闹钟等页面图标，但当前代码里未看到对应传感器、BLE 同步或健康数据链路
- 时间天气任务已存在，但更偏向联网时间更新与页面刷新，不等于 RTC 已接入
- 功耗检查清单已存在，但尚未看到板级 PMIC 控制闭环

## 推荐接入顺序

1. `AXP2101`
   - 先拿到供电轨、电池、充电和中断状态
2. `PCF85063ATL`
   - 再补本地 RTC 保时与唤醒链路
3. `QMI8658C`
   - 最后做运动/姿态/手表场景数据链路

## 为什么这样排

- 电源和 RTC 是低功耗、可靠启动、离线时钟和续航体验的基础设施
- IMU 更偏上层功能，没有稳定电源与时间基线时很容易反复返工

## 适用边界

- 本文用于规划和排障优先级，不代表已经完成硬件可用性验证。
- 真正开始接入某个器件前，仍应先做最小驱动探测、I2C 扫描或中断观测。
