# Network Provisioning Custom Upper Architecture Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将当前仓库从历史 `wifi_provision + network_service` 底座，迁移到“官方 `network_provisioning` + 自定义上层网络架构”，同时保留 AP 浏览器自定义网页前端与当前 Wi-Fi 管理页产品语义。

**Architecture:** 底层 provisioning 会话统一改由官方 `espressif/network_provisioning` 承担；中间通过 `network_provisioning_adapter`、`ap_portal_adapter` 做适配；上层新建 `wifi_control / ble_control / network_credentials / network_manager` 作为正式控制面与编排层。过渡阶段允许 `main/services/network_service` 保留为薄 shim，待 UI 与业务层迁移完成后再删除旧 `components/wifi_provision`。

**Tech Stack:** ESP-IDF v5.5.3、`espressif/network_provisioning`、FreeRTOS、NVS、ESP HTTP Server、LVGL 9.3、Python `unittest`

---

## 关联规格

- Spec: `docs/design/specs/2026-04-18-network-provisioning-custom-upper-architecture-design.md`

## 本轮范围锁定

- 第一阶段只重建设备端底座，不实现微信小程序 BLE 客户端。
- AP 路径采用“自定义网页前端 + 官方 SoftAP provisioning 内核”，不修改官方组件源码。
- 默认 provisioning transport 只保留 `BLE / SOFTAP`，不再保留 `AUTO`。
- recent Wi-Fi 自动连接失败后，设备自动进入用户设置的 provisioning transport。
- 主界面恢复蓝牙图标，作为 BLE 总开关，而不是 BLE 配网入口。
- 旧 `main/services/network_service` 允许过渡期存在，但只能逐步退化为薄 shim。
