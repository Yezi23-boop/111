# Style Profile

## 目标文体

中文工程竞赛作品报告。风格正式、清楚、证据导向，面向评委快速理解作品的实用价值、技术路径、完成程度和创新点。

## 语言规则

- 用“本作品”“系统”“手表端”“服务器端”“Hermes”作为稳定主语，避免人称代词。
- 每段尽量只承担一个功能：背景、方案、实现、结果或不足。
- 对已实现内容使用确定表达；对规划能力使用“预留”“后续将”“可扩展为”。
- 避免宣传口号式语言，少用“革命性”“颠覆性”“全场景”“遥遥领先”等夸张词。
- 所有指标必须有证据，没有证据就不写具体数值。
- 图表说明独立成句，不重复图内文字。

## 推荐句式

- “本作品面向……问题，设计……系统。”
- “手表端负责……，服务器端负责……，Hermes 负责……。”
- “为降低误报，系统采用……策略。”
- “当前已实现……；后续将进一步完善……。”
- “根据板端日志（`board_logs/...`），……”
- “实测结果为……”

## 图表与匿名规则

- 图片以实物照片、界面截图、测试日志/仪器截图为主，TikZ 架构图作为辅助。
- 所有图片中不得出现学校名称、指导老师、真实服务器地址、API key、token、私人数据。
- 代码截图只展示关键逻辑，不展示本地绝对路径和敏感配置。

## 字数控制

- 摘要 800 字内；功能与特性、应用领域、主要技术特点各 400 字内；主要性能指标、主要创新点、设计流程各 200 字内。
- 可扩展之处 300 字内；心得体会 1000 字内。
- 编译 PDF 后可用字数统计脚本核对，确保不超限。

## 目标场景期望

评委希望看到：
1. 清晰的问题定位与应用场景；
2. 与 ESP32-S3 / 嵌入式芯片紧密结合的技术方案；
3. 可验证的完成证据（实物、界面、日志、测试数据）；
4. 诚实的不足与可扩展方向。
